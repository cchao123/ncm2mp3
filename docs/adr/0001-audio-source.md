# ADR-0001：音频来源改为 API 直链下载，NCM 解密降级为兼容分支

- 状态：**已接受**
- 日期：2026-07-26

## 背景

原项目的输入前提是「用户已用网易云官方客户端把歌下载成 `.ncm`」，核心资产是 `ncm_to_mp3.py` 中约 150 行的 NCM 容器解密逻辑（AES-ECB 解密 RC4 密钥 → RC4 变体解密音频流）。

新需求要求「扫码登录」+「下载后直接转 MP3」。这两条与原有前提**互斥**：登录之后走 `song/url` 拿到的是明文音频直链，下载到的是 mp3 或 flac，不是 `.ncm`，不存在需要解密的容器。

即：做了扫码登录，NCM 解密就不再位于主链路上。

## 决策

主链路采用 **API 直链下载**：

```
扫码登录 → 持有 Cookie → 浏览歌单/搜索 → 取直链 → HTTP 下载 → 落盘
```

NCM 解密逻辑**保留**，但降级为一条独立的兼容分支，只服务一个场景：用户手头已有的历史 `.ncm` 文件（如 `target/` 目录下那几个）。它不参与主链路，不阻塞主链路的任何功能。

## 权限边界（硬约束）

只下载**当前登录账号权限范围内**的曲目——免费曲目、账号会员权限覆盖的、已购的。

不实现任何绕过版权限制、破解无版权或未购曲目的能力。这条边界与原 README 中「仅供个人学习、研究和备份合法拥有的音频文件」的定位一致，不因为增加了登录功能而放宽。

## 后果

**正面**
- 用户不再需要先开官方客户端下载，闭环在单个应用内完成
- 直链多为明文，省掉整条解密链路

**负面**
- 引入对**非官方接口**的依赖。这些接口由社区逆向得出，随时可能失效且不会有任何通知。所有依赖它的功能必须能优雅降级，不能让整个应用不可用（见 [glossary](../glossary.md) 中「非官方 API」条目）。
- 引入账号凭据的持有与存储问题（见 ADR-0004，待写）
- 引入服务端风控风险：批量取直链会触发频率限制，可能导致账号受限。必须有节流，不能放任并发（见 ADR-0005，待写）
- 项目性质从「本地文件格式转换工具」变为「联网的账号型客户端」，README 的免责声明范围需要相应修订

## 待验证（阻塞性）

在写任何生产代码之前，必须用真实账号跑通一次最小 spike，确认：

1. 扫码登录三步流程（取 unikey → 生成二维码 → 轮询状态）实际可用
2. `song/url` 各音质档位返回的**实际**内容类型（这是 ADR-0003 的前提）
3. 直链的有效期与是否需要携带 Referer 等请求头

spike 未通过前，本 ADR 的全部后续设计都是纸面推测。
