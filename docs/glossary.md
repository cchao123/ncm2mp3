# 术语表 (Glossary)

本文件在设计访谈过程中持续维护。目的是让「下载」「转换」「音质」这类被日常语言磨平的词，在本项目里有唯一含义。

状态：**草稿**，随访谈推进修订。

---

## 1. 文件与加密

**NCM**
网易云音乐官方客户端下载后落盘的加密音频容器。文件头魔术字 `CTENFDAM`（8 字节）。
内部结构依次为：RC4 密钥段（XOR `0x64` + AES-128-ECB 保护）、元数据段（XOR `0x63` + Base64 + AES-128-ECB）、CRC32、专辑封面 JPEG、RC4 加密的音频流。
注意：NCM 是**容器**，不是编码格式。

**CORE_KEY / META_KEY**
硬编码于官方客户端内的两把 AES-128-ECB 密钥，分别用于解出 RC4 密钥、解出元数据 JSON。见 `ncm_to_mp3.py` 中 `NCMDecryptor` 的类常量。

**key box**
RC4-KSA 生成的 256 字节置换表。音频流用它的一个变体做逐字节异或（非标准 PRGA）。

**内部格式 (inner format)**
NCM 解密后音频流的**真实编码**（`mp3` / `flac`）。这是「要不要转码」的唯一判据——内部已是 mp3 时任何转码都是纯粹的质量损失。
元数据 JSON 的 `format` 字段声明它；文件头嗅探是兜底手段。

**UC 缓存**
网易云的播放缓存文件 `.uc` / `.uc!`，加密方式与 NCM 不同（定长密钥 XOR）。**本项目当前不处理**，术语上不要与 NCM 混用。

## 2. 登录与账号

**扫码登录 (QR Login)**
三段式流程：申请一次性令牌 → 由令牌生成二维码 → 轮询令牌状态直到手机端确认。全程不接触用户密码。

**unikey**
扫码登录的一次性令牌，有效期约 3 分钟。过期后必须重新申请，二维码不可复用。

**QR 状态码**
轮询返回的状态机取值：
- `801` 二维码已生成，等待扫描
- `802` 已扫描，等待手机端点击确认
- `803` 确认成功，随响应下发登录 Cookie
- `800` 二维码已过期

**MUSIC_U**
登录成功后下发的核心身份 Cookie，代表长期登录态。**等价于账号凭据**，其存储位置与保护方式是一个必须显式决策的安全问题（见 ADR）。

**非官方 API**
网易云未公开发布、由社区逆向得出的 HTTP 接口（含 weapi/eapi 的参数加密约定）。
本项目对它的唯一正确假设是：**它随时可能失效，且失效不会有任何通知**。任何依赖它的功能都必须能优雅降级，不能让整个应用不可用。

## 3. 下载与转换

**直链 (song url)**
调用接口换取的音频文件 HTTP 地址，通常有较短的有效期。返回内容受账号权限与曲目版权状态约束。

**音质等级 (level)**
请求直链时声明的目标音质档位（standard / higher / exhigh / lossless / hires）。
**服务端返回的实际音质可能低于请求值**，取决于账号权限和曲目本身有无该档位。请求值 ≠ 到手值，二者在模型里必须是两个字段。

**改封装 (remux) —— 与「转码」严格区分**
- **改封装**：不重新编码，仅改变容器/落盘扩展名。无损、快。NCM 内部是 mp3 时的正确操作。
- **转码 (transcode)**：解码后重新编码。flac → mp3 时**不可逆有损**。
仅当二者被区分开，「都搞成 MP3」这句话才有确定含义。

**ID3 标签**
写入 MP3 文件内部的元数据（标题 / 艺术家 / 专辑 / 封面图）。与「文件名叫什么」是两件独立的事——音乐库软件读的是 ID3，不是文件名。
当前脚本只做了文件名，没做 ID3，且把 NCM 里的封面直接丢弃。

**输出库 (Library)**
转换产物的落盘根目录及其组织方式（平铺 / 按艺术家-专辑分层）。「打开目录」这个需求指向的就是它。

## 4. 应用域

**Job**
一个可观察、可重试、可取消的工作单元。至少区分两类：下载 Job、转换 Job。二者的失败原因和重试语义完全不同（网络失败可重试；解密失败重试无意义）。

**Reveal**
在系统文件管理器中定位到某个文件并选中它，区别于「打开该文件所在目录」。macOS 上分别对应 `open -R` 与 `open`。

## 5. 任务与状态

**曲目可用性 (availability)**
当前登录账号对某曲目**是否有下载权限**。与曲目「是否存在」「能否试听」是不同的事。

四态枚举（`client.rs::Availability`），分界依据是重试语义完全相反：

| 状态 | 含义 |
| --- | --- |
| `Downloadable` | 当前账号可下载 |
| `VipOnly` | 需要会员 |
| `PayAlbum` | 需单独购买（数字专辑） |
| `Unavailable` | 无版权 / 已下架 / 地区限制 |

后三者**重试无意义**，直接记录跳过（ADR-0009）。搜索入口会大量遇到，UI 必须提前明示而非让用户点击后收到语焉不详的失败（ADR-0007）。

判定取自搜索结果的 `privilege` 字段，以 `dl`（账号可下载的最高码率）为首要依据——服务端已把权限算进去了。映射表见 [ADR-0007](adr/0007-mvp-scope.md)。

> 这是**预判**而非保证。最终判据仍是 `song/url` 是否返回非空直链。

**瞬时失败 vs 终局失败**
- **瞬时**：网络抖动、限流、直链过期。重试有意义，做有限次即时重试。
- **终局**：权限不足、曲目下架。重试无意义，直接跳过并计入清单。

把两者混为一谈，会让一次 WiFi 波动产生几十条无谓的失败记录。

**去重依据**
判断一首歌是否已下载，依据是 **SQLite 索引中的曲目 ID**，不是文件名、不是目录结构。

但跳过之前必须**校验文件确实还在磁盘上**——用户可能已在 Finder 里删掉了它（ADR-0009）。

**平铺 (flat layout)**
所有产物落在同一个输出目录，不建层级，区分度全部由文件名承载（ADR-0008）。因此文件名清洗规则的严格程度直接决定了输出库是否可用。
