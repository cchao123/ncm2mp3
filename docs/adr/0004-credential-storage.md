# ADR-0004：登录凭据存入系统钥匙串

- 状态：**已接受**
- 日期：2026-07-26

## 背景

扫码登录成功后下发的 `MUSIC_U` Cookie 是长期登录态，**等价于账号凭据**。持有它即可以用户身份调用接口。

需跨 macOS 与 Windows（ADR-0002）。

候选方案：

| 方案 | 问题 |
| --- | --- |
| 应用目录下的加密文件 | 解密密钥必须存在同一台机器上，本质是自欺欺人的混淆而非加密 |
| 完全不持久化 | 每次启动都要掏手机扫码；与「保守串行、长任务、关窗续传」的使用模式严重冲突 |

## 决策

存入**操作系统凭据管理器**：macOS 用 Keychain，Windows 用 Credential Manager，通过 `keyring` 类 crate 统一抽象。

## 约束

- 凭据**只在需要发起请求时读取**，不在应用内存中长期驻留，不写入任何日志
- 日志、错误上报、崩溃信息中出现 Cookie 值一律视为缺陷
- 必须提供显式的「退出登录」，清除钥匙串条目而不只是清内存
- 凭据失效（服务端登出、过期）时，应用应引导重新扫码，而不是把一堆 401 当成网络错误反复重试

## 后果

- 凭据受系统级保护，其他应用无法读取
- 两套平台 API 需要抽象层，且测试必须在两个平台上各跑一遍——这是选择跨平台的既定成本
- 用户在系统钥匙串工具里能看到本应用的条目，这是正确且透明的行为
